# 手工织锦纹样排版台

直接打开 `index.html` 使用（三份业务源码为普通脚本，无需构建、双击即可运行）。

## 功能

- **多套方案并行保留**：新建、切换、删除方案；每套方案独立记录网格、色线与选色，
  切换时画布、用色统计、预览与断线风险均跟随对应方案（切换前自动写回当前方案，不会被覆盖丢失）。
- **库房库存与缺线阻断**：左侧可按色线登记库存（留空表示不限）。
  - 库存不足的颜色在选色板上标「缺」；
  - 已画进网格但库存不够的格子按颜色单独计数，并统计缺线格合计；
  - 缺线时右侧给出排产阻断原因，导出 JSON 中带 `blocked` 与 `blockingReasons`。
- 保留原有：网格绘制、单点/十字/小菱形纹样块、撤销重做、换色过密断线风险、本地保存。
- **导出 JSON**：导出的是带缩进的纯 JSON 文件（`brocade-pattern-<方案名>.json`），
  可直接打开查看，包含网格、色线、用量、库存、缺线计数与阻断原因。

## 源码结构（三份独立业务源码）

| 文件 | 职责 |
| --- | --- |
| `js/canvas-data.js` | **画布数据**：网格/纹样纯数据模型、填色与撤销重做、用量与缺线计算、断线风险。不依赖 DOM，供后续对接不同织机直接取数据。 |
| `js/scheme-store.js` | **方案读写**：多方案与库房库存的 localStorage 持久化、方案增删切换、导出 JSON。只处理可序列化数据。 |
| `js/page.js` | **页面操作**：DOM 渲染与交互，串起画布数据与方案读写。 |

后续接入织机时：从 `PatternCanvas` 取网格数据、从 `SchemeStore` 读写方案，页面层无需改动；
方案读写也可整体替换为接口实现而不影响画布数据模块。

## 数据兼容

首次打开新版时，会自动把旧版单方案数据（`zfl31Pattern`）迁移为「初始方案」，之后使用 `zfl31Schemes.v2`。
